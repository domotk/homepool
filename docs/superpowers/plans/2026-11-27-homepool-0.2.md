# HomePool 0.2 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Cover a private pool's whole year in HomePool:
- season state;
- winter product;
- configurable tasks and checklists;
- full manual chemistry;
- water treatments with calculated doses.

**Architecture:**
- New pure modules in `custom_components/homepool/pool/` hold the rules, with no Home Assistant imports:
  - `tasks.py`;
  - `season.py`;
  - `checklists.py`;
  - `readings.py`;
  - `dosing.py`;
  - `treatment.py`.
- `coordinator.py` only wires them to state, the store, the ladder inputs, alerts and events.
- New entities go in the existing platform files.
- New services go in `__init__.py` and `services.yaml`.
- All interface text goes in `scripts/generate_strings.py`.

**Tech Stack:**
- Python 3.13/3.14;
- Home Assistant custom integration;
- pytest with `pytest-homeassistant-custom-component`;
- freezegun.

**Spec:** `docs/superpowers/specs/2026-11-27-homepool-0.2-design.md` (Spanish). Read it whole before Task 1, along with `AGENTS.md` and `docs/architecture.md`.

## Global Constraints

- **Keys never change.** The existing entity keys, `reason_key` values, task keys (`backwash`, `filter_cleaning`, `ph_calibration`), event names and card attributes keep their names. Only add.
- **The store reads anything 0.1.4 wrote.** New fields get defaults. `STORAGE_VERSION` and `CONFIG_VERSION` stay at 1.
- **`pool/` and `modes/` import nothing from Home Assistant.** Times arrive as `date`/`datetime` arguments.
- **Interface text only through the generator.** Edit `scripts/generate_strings.py` as `(english, spanish)` pairs, then run it. Never hand-edit `strings.json` or `translations/*.json`.
- **Runtime text goes in `texts.py`**, in both `en` and `es`. Every new `reason_key` gets a `texts.REASONS` entry in both languages.
- **No runtime requirements** (`manifest.json` `requirements: []`).
- **`winter_passive` never lets HomePool run the pump.** Not the mode, pH, freeze protection, a manual cycle or a treatment. A pump switched on by hand is switched off again; only hands-off is above it.
- **HomePool never changes `season_state` on its own.** It only proposes.
- **Every dose is shown with its inputs** (quantity, unit, product, concentration, volume) and the note to check the product label.
- **Defaults are copied from the spec:**
  - winter product 1 per 50 m³ (0.02/m³) every 56 days;
  - backwash 14 days in swimming and 112 pump hours in `winter_active`/`opening`;
  - `ph_calibration` 180 days for new installs;
  - `water_test` 7 days in swimming and 14 in `winter_active`;
  - `skimmer_baskets` 7 days;
  - `cell_cleaning` 90 days;
  - `filter_media_check` 1825 days;
  - opening proposal 14 days before the season;
  - proposal reminder every 7 days;
  - shock rise: light 10, green 15, dark 20 mg/L;
  - calcium hypochlorite 65 %, sodium hypochlorite 150 g/L, dichlor 56 % (raises CYA about 0.9 mg/L per mg/L);
  - shock 24 h, clarifier 48 h, flocculant mixing 2 h and settling 12 h;
  - ranges: TA 80–120, CH 200–400, CYA 30–50 (salt) or 30–80 (not salt), combined chlorine ≤ 0.6;
  - stale after: ph 7 days, free_chlorine 7, salt 30, total_alkalinity 30, calcium_hardness 90, cyanuric_acid 90, combined_chlorine 14.
- **Verification commands:**
  - tests: `.venv.nosync/bin/python -m pytest -q -p no:logging tests/`, plus the same with `.venv314.nosync` before the final task;
  - text: `.venv.nosync/bin/python scripts/generate_strings.py` after any interface text.
- **Commits** end with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Work on branch `feat/v0.2` from `main`.

## Review Focus

1. **Restart mid-treatment or mid-settling.** The phase, its counted seconds and the dose survive a reload, and the pump goes back to what the phase wants. Test in Task 7.
2. **Upgrading a 0.1.4 store during the season with the chlorinator off by hand.** It lands in `winter_active`, the pump keeps following the mode, and it is never `winter_passive`. Test in Task 3.
3. **A pump switched on by hand in `winter_passive`.** It is off again within one evaluation. With hands-off on, it is left alone. Test in Task 3.
4. **A manual reading older than its stale age.** It no longer feeds the chlorine target, `salt_low` or `<kind>_out_of_range`, and `reading_stale` lists it. Test in Task 6.
5. **Frost during flocculant settling.** The pump runs and the treatment alert says settling is interrupted. Once the frost ends, the pump is off again and the time under frost was not counted. Test in Task 7.
